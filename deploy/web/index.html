            The pipeline

            How a change reaches this network

            1. Intent

              One YAML file describes the fabric: switches and their AS numbers, tenants, VLANs, servers and their ports, the ISP policy, BFD timers. Nothing else is written by hand.

            2. Render

              Python and Jinja turn the intent into an FRR config and a Linux script for every device. Both are committed, so a pull request shows the exact config lines it changes.

            3. Static proofs

              FRR parses every config. Batfish then models the whole network from the configs alone and proves the intent: every session, route targets, tenant isolation, only summaries to the ISP.

            4. Live lab on GitHub

              The fabric boots in containerlab on GitHub's machine. 58 tests check sessions, BFD, ECMP, EVPN, routing tables and every ping, then freeze a spine, cut cables and stop a border, timing the failover.

            5. Deploy agent

              This server pulls main once all three checks are green; GitHub holds no key to it. Configs go out with frr-reload one router at a time, canary first, each checked before the next. Any failure rolls back.

            6. Every minute, every night

              Every minute the agent compares each router with Git and undoes anything typed by hand. Every night the failure tests run again here, and the numbers above come from that run.
